# 暨南校史数字人

一个**单文件**的校史问答页面：双击 `交付\暨南校史数字人.html` 就能用，不用装环境、不连网也能答（连不连网只决定答得好不好）。知识库 328 条带出处的问答、检索算法、校园地图面板、数字人立绘全都内嵌在那一个 2.4 MB 的文件里。

讲解员叫**阿鲸**，是本项目自拟的形象，不是校徽或校史里的元素（校徽上画的是帆船）。本文件只讲**五层目录之间的关系**，每层的细节在各自的 README 里，不在这里重复。

---

## 目录

```
暨大校庆\
├── 暨大史料\   ← 证据层：官网原文照录、371 张史照与图注、OCR 文本   【只增不改】
├── 知识库\     ← 数据层：19 个分片 / 328 条问答 / 1497 种问法       【可改，改完要校验】
├── 应用\       ← 代码层：页面模板、检索打分、打包与校验脚本
├── 交付\       ← 产出层：单文件 HTML + 本说明的副本               【全是生成物，不要手改】
├── 原图\       ← 素材层：用户提供的三张源图（校园地图、角色立绘、角色设定表）
└── README.md   ← 本文件
```

**五个目录不是并列的，是一条链**：

```
暨大史料\  ──抄录、比对──▶  知识库\  ──打包──▶  交付\暨南校史数字人.html
   （证据）                    （数据）              （能直接发出去的成品）
                                  ▲
   原图\ ──离线预处理──▶ 应用\ 的派生图（底图/立绘/史照/校徽）
```

- **暨大史料\ 只增不改**。它是"证据"，改了就没法溯源；发现错误是**补录**一份说明，不是回头改原文。
- **知识库\ 是产品数据，可以自由增删改**。每条答案用 `local_refs` 指回史料、用 `evidence` 存原文片段——改答案不需要动史料。
- **应用\ 是代码**，`build.mjs` 把 知识库\ + 页面模板 + 派生图合成那一个 HTML。改数据不用改代码。
- **交付\ 里两个文件都是生成物**：HTML 由 `build.mjs` 生成，`README.md` 是 `应用\README.md` 的逐字节副本（给人发出去时一并看）。**手改这两个文件，下次打包就没了。**

## 哪些能改，改完要跑什么

| 想做什么 | 改哪里 | 改完跑 |
|---|---|---|
| 补一条问答 / 改答案 | `知识库\shards\*.json` | `node 知识库\校验.mjs` → `node 应用\build.mjs` |
| 改阿鲸的口吻、自称 | `知识库\persona.json` | `node 应用\build.mjs` |
| 改页面样式、交互 | `应用\template.html` | `node 应用\build.mjs` → 两个 verify |
| 换底图 / 立绘 / 史照 | `原图\` 或 `暨大史料\` | `应用\tools\` 里的脚本 → `node 应用\build.mjs`（见 `应用\tools\README.md`） |
| 补史料 | `暨大史料\`（只增不改） | 不用跑什么——它不参与打包；要让页面用上，得先写进知识库 |
| 改 `应用\README.md` | 它本身 | `cp 应用\README.md 交付\README.md`（两份必须逐字节一致） |

派生图（底图、立绘、史照、校徽）是**离线**缩好的，构建只读成品、不做图像处理——所以换图要多跑一步 `应用\tools\` 的脚本，不能只重打包。

## 常用命令

```powershell
# 打包（改完数据/页面后必跑；产出 交付\暨南校史数字人.html）
node 应用\build.mjs

# 打包后的两道校验
node 应用\verify.mjs        # 真执行页面脚本，抓运行期错误
node 应用\verify-map.mjs    # 真跑一遍地图面板（悬浮/点击/切页）

# 评测与数据校验
node 应用\eval.mjs          # 185 条留出集上的离线指标
node 知识库\校验.mjs         # 19 分片 / 328 条 / 问法冲突 / 计数一致

# 交付前
node 应用\tools\gate-test.mjs   # 反向测试打包闸门（故意弄坏，看是否真中止）
node 应用\tools\shot.mjs map    # Edge 无头截图，补"须在浏览器里逐条目视"那一步
```

打包内置硬闸门：密钥泄漏、地图四向同构对不上、占位符没替换、人设与防幻觉规则的顺序……一律**中止打包**，不留到运行期才炸。逐条清单见 `应用\README.md`。

## 公开仓库说明（本仓库刻意不含什么）

本仓库放的是**源码与数据**。以下几类内容按 `.gitignore` 排除，是**有意为之，不是丢失**：

| 排除项 | 原因 | 本地是否仍有 |
|---|---|---|
| `应用\fallback-models.enc` | 内置兜底线路的密文。解密口令以掩码数组存放在 `应用\template.html` 里，任何人拿到该文件都能解出真实 API 密钥 | 有 |
| `交付\*.html` | 上一条的密文被整个内联进了成品，会同样泄漏密钥 | 有，`node 应用\build.mjs` 可重建 |
| `暨大史料\`（约 143 MB） | 暨南大学官方图集（371 张史照与图注），版权属学校，不宜在公开仓库再分发 | 有 |
| `原图\`（约 28 MB） | 用户提供的源图（校园地图、角色立绘、角色设定表）；已离线缩放为 `应用\` 内的派生图，构建只读派生图 | 有 |

**clone 之后能做什么**：`node 应用\build.mjs` 可完整重建页面——构建在缺少 `fallback-models.enc` 时会提示「不含内置兜底线路」，页面转而要求填入自己的模型密钥；这对任何开源 LLM 应用都是正常姿势。

**溯源说明**：知识库条目的 `local_refs` 指向 `暨大史料\`，该目录不随仓库分发，故逐条核对原文需自备语料。
