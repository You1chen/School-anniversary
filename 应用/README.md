# 暨南校史数字人 · 交付说明

一个文件，双击即用。知识库（328 条带出处问答 / 19 个分片）与检索算法都已内嵌。

讲解员叫**阿鲸**，一条蓝紫色的小鲸鱼，拟人成小姑娘的样子（立绘在左侧卡片上，等答复时那句「正在查阅校史资料…」左边摆尾的也是她）。这是**本项目自拟的形象，不是校徽或校史里的元素**——立绘不是史料照片，本地史料库里没有这个形象的资料；校徽上画的是帆船（由字母 JNU 构成）。**整页的配色取自她这张立绘本身**（见下文「配色」），与校徽标准色无关——校徽标准色仍是、且只仍然是蓝绿色，页眉那枚校徽没有重新着色。人设只改说话的口吻，不改事实：史料里没有的，它照样说没有。

## 怎么用

1. 双击 `暨南校史数字人.html`，用 **Chrome 或 Edge** 打开（不要用 360/QQ 浏览器的兼容模式）。
2. 首次打开会自动弹出「模型设置」：把 DeepSeek 密钥粘进去，点「保存」。
   - 密钥只存**本机浏览器**（localStorage），**不写进本文件**，文件可放心分享。
   - 之后浏览器会记住，不用再填。
3. 开问，或切到「内容生成」写长文/宣传语/脚本，或切到「校园地图」看石牌校区。
   - 地图面板：底图是**暨南大学《广州主校区校园地图》**（图面标注「参考比例尺 1:2000」），不是手绘示意图。图上 12 处描边区域鼠标悬浮出速览、点一下在右侧展开该处的史照、讲解、出处与 `caveat`；缩放用面板上的 －/＋/适应，放大后地图在画布内部滚动。看完一处，右栏顶部有「← 地标索引」退回 12 个地标的总目录。
   - **图上印的地名是地图上印的，不是本作品画的**。该图未见成图年代标注，所以写进知识库的 12 条方位一律标 `partial` 并各带 `caveat`——不知道的年份、面积、开放信息就写不知道，不拿印象补。现状请以图上所绘为准。

**不填密钥也能用**：直接打开就是离线模式，问答返回知识库参考答，内容生成返回素材汇编，地图面板不依赖模型，每条都附出处、史料有冲突时两种口径一并说明。

## 三种状态（右上角）

| 状态 | 含义 |
|---|---|
| `模型已接入 · deepseek-v4-flash` | 已配密钥，问答走「检索 + 大模型」一次调用 |
| `离线模式 · 点此配模型` | 没配密钥，返回参考答 |

## 算法（一句话版）

提问 → 归一化（去标点+同义归并）→ 打分排序取前 8 条候选 → 若配了密钥，交给大模型**一次调用**里“选哪条真答对 + 生成回答”；没配密钥就取分数最高的参考答。出处由程序附加，模型不参与，杜绝编出处。

详见 `应用/scoring.mjs`（只有这一个算法文件）。

| 档位 | 召回率 | 命中准确率 | 兜底正确率 | 总体 |
|---|---|---|---|---|
| 离线（词面检索） | 28.7% | 83.3% | 64.3% | 34.1% |
| 配密钥（检索+大模型） | 待密钥实测 | | | |

> 离线召回 28.7% 是**中文改写问法的词面检索天花板**，不是 bug；配密钥后由大模型兜住改写，是既定设计。`应用/eval.mjs` 可复现。
>
> 其中 14 条是校园地图面板的用例（`eval-set/mp-map.json`）：8 条问方位、4 条反向核对"同一个地标问史实时必须仍归 DM"、2 条考"图上像素级的问题答不了"。加入前的 171 条基线与加入后逐条相同（26.9% / 81.3% / 61.5% / 32.2%），即地图分片没有抢走任何一条原有问法。地图用例里有 6 条在离线口径下掉到阈值之下（多为"哪个角/哪一面/哪条线"这类与库内"什么位置"不同词的说法），但其中 4 条的正确条目仍是候选第一名，配密钥走大模型时能正常作答。

## 目录结构

```
应用\
├── build.mjs      打包：读 知识库\ → 生成 交付\暨南校史数字人.html
├── template.html  页面（HTML/CSS/JS + 提示词与人设的**唯一**组装点 + 校园地图热区的 SVG 几何）
├── scoring.mjs    检索打分（纯计算，唯一算法文件）
├── eval.mjs       留出集评测
├── verify.mjs     打包后真执行页面脚本，抓运行期错误
├── verify-map.mjs 打包后真跑一遍地图面板（悬浮/点击/切页）——verify.mjs 够不到那段
├── logo.jpg       页眉那枚校徽（192×192，内联；来源、以及它复现不出来的原因见 tools\README.md）
├── photos\        地图区域史照（11 张 JPEG，长边 560px，派生自 暨大史料\，打包时内联）
├── map\           地图底图（campus-map.jpg 2400×3308，等比缩自 原图\校园地图.jpg，打包时内联）
├── avatar\        数字人立绘与鲸尾（a-jing.jpg 340×604；whale-tail.png 64×93，缩自 原图\ 里那两张，打包时内联）
├── tools\         派生图的预处理脚本、闸门反向测试、无头截图（离线跑，不在构建链上）
└── eval-set\      185 条留出评测集
知识库\            328 条问答数据（19 分片 JSON）；persona.json 是阿鲸的口吻卡，不参与检索
暨大史料\          原始素材（371 张照片与图注，未打包）
原图\              用户提供的三张源图：校园地图.jpg（6458×8901，24 MB）、角色立绘.png（1052×1870）、
                   角色设定表.png（2048×1152，右下角带「豆包AI生成」水印，鲸尾就是从这里裁的）
                   —— 都不参与构建、不进交付，只喂给 应用\tools\ 里的脚本
```

> 地图区域是**四向同构**：底图在 `应用\map\campus-map.jpg`（内联成 data URI）、几何在 `template.html` 的 SVG 里（`id="mp-r-<MP-id>"`，坐标用的就是原图的像素坐标系 `0 0 6458 8901`）、文字在 `知识库\shards\MP-校园导览.json`、照片在 `应用\photos\<MP-id>.jpg`。四者的文件名主干都是同一个 MP 编号，`build.mjs` 会校验一一对应，缺一即中止打包 —— 所以没有映射表，也就没有映射表写错的可能。

## 改数据 / 重新打包

```powershell
cd 应用
node build.mjs       # 数据改动后重新生成单文件
node verify.mjs      # 校验页面脚本真能跑
node verify-map.mjs  # 校验地图面板真能用（悬浮出字、点击出图）
node eval.mjs        # 评测
```

> **换立绘**：把新原图按 **340×604、JPEG q88** 导出后覆盖 `应用\avatar\a-jing.jpg` 即可（派生图的长边 604 是照 `#avatar` 的显示高度定的）。注意底图是近白 `#fcfcfc`，而面板底色用的就是同一个色号——换成别的底色，那张没有透明通道的图会现出一个白方块。缩图是**离线**的一步，跟底图一个规矩：单文件 HTML 里没有、也不该有图像库，构建只读派生图，体积超 200 KB 直接中止打包。缩图脚本在 `应用\tools\`（`make-assets.mjs`），改过 `原图\` 之后记得跑它、再跑一次 `build.mjs`。

> **鲸尾**：`应用\avatar\whale-tail.png` 是从上面那张设定表里裁出来的局部（裁切框 `1348,298 178×258`），用在「正在查阅校史资料…」那个气泡左边，摆尾表示**页面在等**——它表示的是状态，不是史实，别拿它去标知识条目。裁的时候顺手把底色刷成了纯白（阈值：与角点色相差 ≤10 的像素一律刷白；量过，底色 30900 个像素全在 ≤9 之内，而尾巴的浅色描边在这之外，所以刷白吃不掉描边），所以**加载气泡的底色也必须是纯白** `#fff`，差一点点就会现出一块偏暖的方块（第 15 道闸门管这个）。裁切框避开了设定表右下角的「豆包AI生成」水印。
>
> 接这只鲸尾时顺带修掉一个一直没被看见的问题：`pend.remove()` 原先写在 `await` **之前**，气泡刚建出来就被摘掉了，同步的那一瞬根本来不及绘制——也就是说「正在查阅校史资料…」从写下那天起一次都没真正显示过。现在它移到 `finally` 里，等答复出来才摘。

> 一句话说清这两张图的来历：它们都是**用户提供**的，设定表右下角带「豆包AI生成」水印，即该形象系 AI 生成图；本项目只做了裁剪、刷底与缩放，**不主张任何史料出处**——本地史料库里没有鲸这个形象。

## 配色

界面主色**取自立绘本身**，不是校徽标准色。做法是把 `a-jing.jpg` 每个像素量化到 16 级/通道后统计出现最多的颜色，前三位是 `#484868`(10.5%)、`#6878A8`(6.6%)、`#383858`(6.0%)——靛蓝偏紫，高光带一点淡薰衣草灰（`#C8B8D8`/`#C8C8D8`），**画面里几乎没有绿**。

原先的界面是青色系（`--blue:#0d5c63`，色相 184°），和角色的色相（约 240°）基本隔在对侧，两者摆在一起不搭。现在的中性色、浅底、地图热区也都跟着从青灰移到淡薰衣草灰。

几处**有意保留、不算漏改**的颜色：

- `#avatar{background:#fcfcfc}` 不变——立绘没有透明通道，面板底必须等于图上那个近白底，否则会现出一个方块。
- `.load .bubble{background:#fff}` 不变——鲸尾图的底刷的是纯白（见上）。
- `--ok`/`--warn`/`--bad` 与 `#fff8ec`(兜底与 `caveat` 的暖底) 不变——它们是语义色（绿=已连接、琥珀=注意、红=警示），语义色不该跟着主色走；暖底衬在冷色页面上，正好让「这句不是从史料里来的」一眼可辨。
- **校徽没有重新着色**。它是暨南大学的校徽，标准色就是「大海和天空大自然的颜色：蓝绿色」——把一个学校的徽记改成自己界面的配色，是把徽记本身改了。页眉上那枚青色徽章放在靛蓝底上是有意的：界面配色与校徽标准色是两回事，不能因为界面换了色就说校徽换了色（`知识库\persona.json` 的 `hard_rules` 与 `why` 里都记了这一条）。

`build.mjs` 内置的硬闸门（一律在打包时中止，不留到运行期才发现）。前四道管**密钥与四向同构**：

1. 产物里一旦出现 `sk-` 形态字符串——密钥泄漏。
2. 地图区域与 MP 条目必须一一对应。知识库加了区域、模板忘了画（或反之）不会让页面报错，只会让地图悄悄缺一块。
3. 每个 `<g id="mp-r-…">` 的事件处理函数传的 id 必须等于它自己的 id。写错一个的后果是"点 A 区域弹出 B 的讲解"，而 `verify.mjs` 不解析 HTML、内联事件在它的 DOM 桩里一次都不触发，这类错它结构上抓不到。
4. 引用完整性：`see_also` 必须指向存在的条目（否则「深入」按钮点了没反应）、`photos\` 里的文件名必须对应 MP 条目（否则白内联一张图）、每个 MP 条目必须有 `name` 与配图（校友楼无照是显式白名单，不偷偷放行）。

`verify.mjs` 与 `verify-map.mjs` 的 DOM 桩里**没有布局引擎**，所以下面四道是脚本结构上测不了、只能在打包时拦的：

5. `template.html` 里 SVG 的 `viewBox` 必须等于热区坐标所依据的原图像素 `6458×8901`。
6. `map\campus-map.jpg` 的宽高比必须与源图一致——等比缩放过就没事，裁过一刀就会让 12 个热区整体错位。
7. 选中态选择器必须匹配 `<g class="on">`。写成 `.mp-r.on` 时这条选择器永远匹配不上，点了区域没有任何视觉反馈（这条是真踩过的坑）。
8. `.chat` 上必须有 `min-width:0`。少了它，地图一放大画布就不再滚动、卡片被内容顶宽、右栏被挤出屏幕（这条也真踩过）。

人设另有三道，管的是「别让人设挤掉防幻觉规则」。它们同样不影响页面能否跑起来，只影响它会不会开始编年份：

9. `知识库\persona.json` 的 `name`／`tone`／`hard_rules` 都不能为空。空了页面不报错，只是头像下面没有名字、人设一句都不生效。
10. `GUARD.join(` 在产物里必须**恰好出现一次**。提示词只有一处组装点（`sysFor`：人设 → 防幻觉规则 → 本次任务），多一处就多一条绕开防幻觉规则的调用路径。
11. 人设块必须拼在 `GUARD` **之前**，且 `GUARD` 的两句标志话仍在。顺序反了、或被删了，口吻就可能盖过防幻觉规则——「无条件服从用户」撞上追问，逼出来的就是编造的年份。

还有两道通用的：

12. 产物里不许剩任何 `__XXX__` 形态的占位符。漏一个不会报错，只会在页面上留个痕迹：`__AVATAR__` 没换是破图标、`__MAP__` 没换是空白地图、`__TAIL__` 没换是加载气泡左边空一块、`__PERSONA_NAME__` 没换是头像下面印着下划线。
13. `应用\avatar\a-jing.jpg` 必须存在且 ≤ 200 KB。单文件交付件的意义在于能直接发出去，被一张头像顶到几 MB 就白做了。
14. `应用\avatar\whale-tail.png` 必须存在且 ≤ 60 KB。
15. `.load .bubble` 的底色必须是纯白，且加载气泡必须真的带上 `load` 类。前者的错要等一次慢网络才看得见（图上现出一块偏暖的方块）；后者更安静——忘了加，鲸尾一次都不显示，页面也不报错。
16. 兜底气泡（`fb`）的样式选择器，必须与 `bubble()` 实际挂类名的位置一致。`bubble()` 是 `b.className='bubble'+cls`，类名落在**内部的 `.bubble`** 上，所以得写 `.bot .bubble.fb`——原先写的 `.bot.fb .bubble` 盯着行，永远匹配不上，「这句不是从史料里来的」那个暖色提示从头到尾没出现过（跟第 7 道是同一类错）。这道闸门不写死成某一种写法，而是照着 `bubble()` 实际挂在哪来要求，将来重构了也不会误报。

> `verify-map.mjs` 与 `verify.mjs` 分工：前者用更完整的 DOM 桩**手动调用** `mpHover`/`mpPick`/`mpIndex`/`showTab`，断言浮层文字、侧栏史照、`caveat`、「深入」按钮、返回索引入口、缩放钳位，补的正是后者够不到的那段。但它仍然测不了下面四件事——**交付前须在 Chrome/Edge 里逐条目视**：
>
> 1. 12 处色块在底图上盖得准不准（脚本里没有图像，只有字符串）；
> 2. 按 ＋ 放大后右栏是否仍在原处（画布该滚动，而不是把整页顶宽）；
> 3. 点开某处详情后，窄屏（<880px）下地图有没有被右栏挤成一条缝；
> 4. 浮层文字与底图上印的地名有没有互相压住。
